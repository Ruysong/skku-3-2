### DP 상태를 먼저 한 문장으로 정의하기

배열 이름을 `dp`라고 정하는 것만으로는 설계가 끝나지 않는다. 예를 들어 `V[i,w]`는 첫 i개 물건 중에서 총무게가 **용량 w 이하**가 되도록 선택할 때의 최대 이익이다. 용량과 정확한 사용 무게는 다르다. 물건 무게가 2뿐이어도 용량 3에서 그 물건을 넣을 수 있다. 교수님 교안 일부의 exact weight라는 문구를 그대로 적용하면 초기값 0과 점화식의 의미가 어긋나므로, 교안의 실제 표와 알고리즘은 용량 이하의 최적값으로 이해한다.

최적 부분 구조는 현재 문제의 최적해를 구성하는 나머지 부분도 그 조건에서 최적이어야 한다는 뜻이다. 더 나은 나머지 해가 있다면 그것으로 바꿔 전체도 개선할 수 있기 때문이다. 중복 부분 문제는 서로 다른 선택 경로가 동일한 상태에 도달한다는 뜻이다. DP는 그 상태를 한 번 계산한 뒤 저장한다. 모든 부분집합을 출력하는 대신 각 상태의 최적값이나 가능 여부만 저장하므로 많은 경로를 하나로 합칠 수 있다.

top-down은 필요한 상태를 재귀로 호출하고 memo에 저장한다. bottom-up은 의존 상태가 먼저 준비되는 순서로 표를 채운다. 같은 상태 집합을 모두 방문한다면 보통 같은 차수의 계산량을 가지지만, top-down이 도달 가능한 상태만 계산할 수도 있으므로 두 방식이 언제나 정확히 같은 연산 수라는 뜻은 아니다.

### LCS의 상태와 복원

`c[i,j]`를 X의 첫 i개 문자와 Y의 첫 j개 문자의 LCS 길이라고 정의한다. 비어 있는 문자열과의 LCS 길이는 0이므로 첫 행·열은 0이다.

```text
X[i] == Y[j] : c[i,j] = c[i-1,j-1] + 1
X[i] != Y[j] : c[i,j] = max(c[i-1,j], c[i,j-1])
답            : c[m,n]
```

여기서는 문자열을 1부터 세는 표기다. 실제 0-based 코드에서는 문자를 `X[i-1]`, `Y[j-1]`로 접근한다. 일치하는 끝 문자는 두 prefix를 함께 줄인 최적 부분수열 뒤에 붙일 수 있다. 일치하지 않으면 한쪽 끝 문자를 쓰지 않는 두 경우를 비교한다. 표 전체는 `O(mn)` 시간·공간이고, 각 칸에서 선택한 방향이나 값·문자 비교를 이용해 `(m,n)`에서 거슬러 올라가 실제 부분수열을 복원한다. 길이와 복원은 서로 다른 작업이다.

예제 `ABCB`, `BDCAB`에서는 길이 3인 `BCB`를 복원한다. 역방향으로 수집한 문자는 마지막에 뒤집어야 한다. 값이 같은 분기가 여럿이면 다른 최적 부분수열이 나올 수 있으며, 최적해가 항상 유일하다고 가정하지 않는다. 이 부분은 뒤의 LIS에서 `prev`를 저장하는 방법과 연결된다.

### A-2. 문제와 예제 데이터

물건 i의 이익은 `p_i`, 무게는 `w_i`, 선택은 `x_i ∈ {0,1}`이다. 목표는 `Σp_i x_i`를 최대화하면서 `Σw_i x_i ≤ M`을 만족하는 것이다. 반쪽만 담는 fractional knapsack과 달리 한 물건을 넣거나 넣지 않는 두 선택만 있다.

| 물건 | 이익 p | 무게 w |
| --- | ---: | ---: |
| 1 | 1 | 2 |
| 2 | 2 | 3 |
| 3 | 5 | 4 |
| 4 | 6 | 5 |

용량은 `M=8`, 모든 무게의 합은 14이므로 전부 넣을 수 없다. 선택 벡터는 네 개의 0/1이다. 네 물건의 선택 조합은 16개이며 일반적으로 `2^n`개다. 이 중에는 용량을 넘는 조합도 있다. DP가 모든 조합을 실제로 출력하는 것은 아니다. 같은 물건 범위·남은 용량에 대한 최적값을 재사용해 가능한 선택을 빠짐없이 비교한다.

### A-3. Tabulation: 표의 두 축과 점화식

`V[i,c]`는 첫 i개 물건만 허용하고 용량이 c일 때의 최대 이익이다. 행은 고려한 물건 수, 열은 0부터 8까지의 용량이다. 처음에는 물건이 없으므로 모든 `V[0,c]=0`이다. 이 예제는 무게가 양수이므로 용량 0에서도 이익 0이다.

```text
물건 i가 무거워서 못 들어감:
    w_i > c  -> V[i,c] = V[i-1,c]

넣을 수 있는 경우:
    제외 = V[i-1,c]
    포함 = p_i + V[i-1,c-w_i]
    V[i,c] = max(제외, 포함)
```

포함의 경우에도 이전 행 i-1을 보는 이유는 물건 i를 이미 한 번 선택했기 때문이다. 같은 행을 다시 참조하면 동일 물건을 여러 번 사용할 수 있는 다른 문제로 바뀔 수 있다. 용량이 부족하면 포함 분기를 아예 만들지 않는다. 음수 인덱스를 읽고 나서 적당히 0으로 취급하는 구현은 잘못이다.

```text
용량 c       0 1 2 3 4 5 6 7 8
물건 0개     0 0 0 0 0 0 0 0 0
물건 1개     0 0 1 1 1 1 1 1 1
물건 2개     0 0 1 2 2 3 3 3 3
물건 3개     0 0 1 2 5 5 6 7 7
물건 4개     0 0 1 2 5 6 6 7 8
```

첫 행에서는 무게 2가 들어가는 열부터 이익 1을 얻는다. 물건 2까지 허용하면 용량 3에서 이익 2, 용량 5에서 두 물건의 이익 3이다. 물건 3을 넣으면 용량 4에서 이익 5, 용량 6에서 물건 1과 함께 이익 6, 용량 7에서 물건 2와 함께 이익 7이다. 용량 8에서도 물건 1·2·3은 총무게 9라 전부 넣을 수 없다.

마지막 행을 점화식으로 확인한다. `V[4,5]=max(5,6+0)=6`, `V[4,6]=max(6,6+0)=6`, `V[4,7]=max(7,6+1)=7`, `V[4,8]=max(7,6+2)=8`이다. 영상은 이 계산을 조합을 직접 떠올리는 직관으로도 설명한다. 그러나 특정 예제에서 현재 물건의 이익이 크다는 사실을 일반적인 선택 규칙으로 바꾸면 안 된다. 일반 알고리즘의 기준은 항상 포함·제외의 최댓값이다.

### A-4. 최적값에서 실제 선택 복원

`V[4,8]=8`은 최대 이익만 알려준다. 어떤 물건을 담았는지는 행을 거슬러 올라가 알아낸다. 같은 용량에서 현재 값이 이전 행 값과 같으면 물건 i를 제외해도 최적값을 유지한다. 다르면 물건 i를 포함한 분기를 택했으므로 표시하고 남은 용량에서 `w_i`를 뺀다.

```text
(i=4,c=8) : 8 != V[3,8]=7 -> 물건 4 포함, c=3
(i=3,c=3) : 2 == V[2,3]=2 -> 물건 3 제외
(i=2,c=3) : 2 != V[1,3]=0 -> 물건 2 포함, c=0
(i=1,c=0) : 0 == V[0,0]=0 -> 물건 1 제외

선택 x = [0,1,0,1]
총무게 = 3+5 = 8, 총이익 = 2+6 = 8
```

대본은 남은 이익을 빼며 설명하지만, 안전한 표 추적에서는 남은 용량 좌표도 함께 관리해야 한다. 같은 이익 숫자가 다른 열에 있다고 임의로 옮겨 다니지 않는다. 포함·제외가 동점이면 둘 중 하나를 일관되게 선택해 한 최적해를 복원할 수 있다. 표 계산은 `O(nM)` 시간·공간, 표가 있을 때 역추적은 `O(n)`이다. 이 복잡도 설명은 대본을 수식으로 정리한 보강이다.

### A-5. Sets Method: 이익·무게 쌍으로 표현하기

여기서는 순서쌍이 **(profit, weight)**임에 주의한다. `S_i`는 첫 i개 물건을 고려해 남겨둔 후보 쌍의 집합이다. 시작은 아무것도 넣지 않은 `S_0={(0,0)}`다. 새 물건을 포함하지 않는 기존 쌍과, 기존 쌍에 새 물건의 이익·무게를 각각 더한 쌍을 합친다.

```text
물건 i 미포함: S_(i-1)의 쌍을 그대로 유지
물건 i 포함  : 모든 (p,w)에 (p_i,w_i)를 더한 쌍 생성
병합         : 두 후보 집합을 합침
가지치기     : 용량 초과 제거 + 지배되는 후보 제거
```

예제 단계는 다음과 같다.

```text
S0 = {(0,0)}
S1 = {(0,0),(1,2)}
S2 = {(0,0),(1,2),(2,3),(3,5)}

물건 3의 (5,4)를 S2에 더하면
    {(5,4),(6,6),(7,7),(8,9)}
(8,9)는 무게 9 > 8이므로 제외.
(3,5)는 (5,4)보다 이익이 작고 무게도 커서 제외.

S3 = {(0,0),(1,2),(2,3),(5,4),(6,6),(7,7)}

물건 4의 (6,5)를 S3에 더하면
    {(6,5),(7,7),(8,8),(11,9),(12,11),(13,12)}
무게가 8을 넘는 뒤의 세 쌍은 제외.
(6,6)은 같은 이익에 더 가벼운 (6,5)가 있으므로 제외.
중복된 (7,7)은 하나만 보관.

S4 = {(0,0),(1,2),(2,3),(5,4),(6,5),(7,7),(8,8)}
```

### A-6. Dominance rule의 정확한 의미

같은 단계에서 A의 이익이 B 이상이고 A의 무게가 B 이하이며 둘 중 하나는 엄격히 더 좋으면, A가 B를 지배한다. 이후에 추가할 물건들은 두 후보에게 똑같이 남아 있으므로 B에 가능한 추가 선택은 A에도 가능하다. A를 남겨두면 B를 지워도 최적해를 잃지 않는다. `S3`에서 `(5,4)`가 `(3,5)`를 지배하는 것이 그 예다.

대본의 “이익이 증가하는데 무게가 감소하니 wrong”이라는 설명을 수학적으로 잘못된 쌍이라는 뜻으로 외우지 않는다. `(3,5)`도 실제 선택으로 만들 수 있는 유효한 조합이다. 다만 같은 단계에 더 좋은 후보가 있어 **최적값 계산에는 불필요**한 것이다. 용량 초과로 불가능한 조합과 지배되어 제거하는 가능 조합은 제거 이유가 다르다.

집합을 그대로 늘리면 각 물건마다 후보 수가 두 배가 되어 지수적으로 증가할 수 있다. 지배 제거가 실제 후보를 줄여주더라도 입력 수치 제한과 자료구조를 따지지 않고 항상 빠른 다항 시간이라고 보장해서는 안 된다. 정수 용량 M으로 상태 수를 제한할 수 있다는 관점은 pseudo-polynomial 분석과 이어진다. 영상의 “거의 `2^n`”은 무제한 후보 생성의 위험을 설명한 것으로 읽고, tabulation의 `O(nM)`과 혼동하지 않는다.

### A-7. 집합으로 선택 복원

마지막 최적 쌍 `(8,8)`은 S4에는 있고 S3에는 없다. 물건 4를 포함하고 `(6,5)`를 빼면 `(2,3)`이 남는다. `(2,3)`은 S3와 S2 모두에 있으므로 물건 3을 제외한다. S2에는 있지만 S1에는 없으므로 물건 2를 포함해 `(2,3)`을 빼면 `(0,0)`이다. 나머지는 아무것도 넣지 않은 상태여서 물건 1을 제외한다. 결과는 표와 같은 `[0,1,0,1]`이다.

복원하려면 각 단계의 집합이나 부모 상태를 저장해야 한다. 최종 후보 하나만 남겨두고 이전 단계를 지워버리면 원래 선택을 자동으로 알 수 없다. 동점·중복 후보가 있을 때는 한 유효한 부모를 선택하면 된다. 이 점이 최적 이익 계산과 실제 해 구성의 차이다.

### B-2. LIS: 문제의 순서를 보존해야 한다

LIS는 원래 인덱스 순서를 유지하면서 값이 엄격히 증가하는 가장 긴 부분수열이다. 연속일 필요는 없지만 원래 순서를 바꿀 수 없다. 따라서 배열을 값 기준으로 정렬해버리는 것은 원래 LIS 문제를 푸는 방법이 아니다. 값이 같은 두 원소도 엄격 증가 조건에서는 연달아 붙일 수 없다.

영상은 한 예제에서 `1 → 2 → 5`로 길이 3, 다른 예제에서 `2 → 3 → 6 → 9`로 길이 4를 제시한다. 붙여넣은 자막에는 원본 입력 배열의 모든 숫자가 발화되어 있지 않다. 아래 수식과 알고리즘은 재구성할 수 있지만, 말하지 않은 화면의 전체 배열을 임의로 영상 원본처럼 만들지는 않는다.

DAG 모델에서는 원소 A[j]와 A[i]에 대해 `j<i`이고 `A[j]<A[i]`일 때 `j→i` 간선을 둔다. 모든 간선은 오른쪽으로 가므로 사이클이 없다. 한 경로는 하나의 증가 부분수열이다. 보통 그래프 경로 길이를 간선 수로 세면 LIS 원소 수는 경로 길이+1이다. 두 길이를 혼동하지 않는다.

### B-3. 끝 인덱스를 고정한 상태와 점화식

`L[i]`는 **반드시 A[i]에서 끝나는** 증가 부분수열의 최대 길이다. 첫 i개 원소 안에서 아무 데서나 끝나도 되는 최대 길이와 다르다. 끝 원소를 고정하면 이전에 붙일 수 있는 원소의 조건을 정확히 쓸 수 있다.

```text
이전 후보: j < i 이고 A[j] < A[i]
L[i] = 1 + max(L[j] : 이전 후보 j)
이전 후보가 없으면 L[i] = 1
전체 답 = max_i L[i]
```

L[i]를 갱신할 때 필요한 것은 i보다 왼쪽의 상태들뿐이다. 따라서 왼쪽에서 오른쪽으로 계산하고 모든 초기 길이는 자기 자신 하나를 뜻하는 1이다. 전체 답을 무조건 마지막 `L[n-1]`로 정하면 마지막 원소에서 끝나지 않는 최적해를 놓친다. 빈 배열의 길이는 0으로 따로 처리한다.

```text
for i = 0..n-1:
    L[i] = 1
    prev[i] = -1
    for j = 0..i-1:
        if A[j] < A[i] and L[j]+1 > L[i]:
            L[i] = L[j]+1
            prev[i] = j
answer_end = 길이가 가장 큰 L의 인덱스
```

위 의사코드는 영상 설명을 정리한 것으로 판서 코드를 글자 단위로 복사한 것이 아니다. 각 i에서 앞 원소들을 비교하면 `O(n²)` 시간, L과 prev는 `O(n)` 공간이다. 이 문서에서 LIS의 다른 고급 알고리즘을 새 필수 범위로 추가하지 않는다.

### B-4. 정확성과 실제 수열 복원

최적 부분수열이 i에서 끝나고 길이가 2 이상이라면, 바로 앞 원소 j는 반드시 `j<i`, `A[j]<A[i]`를 만족한다. j에서 끝나는 앞부분을 더 긴 수열로 바꿀 수 있다면 i까지의 수열도 길어지므로 그 앞부분은 최적 상태 L[j]로 대표할 수 있다. 모든 가능한 j를 비교하고 자기 자신 하나의 경우도 포함하므로 빠지는 해가 없다. 왼쪽부터 계산하면 이 논리를 인덱스에 대한 귀납법으로 적용할 수 있다.

실제 수열은 갱신을 만든 j를 `prev[i]`에 저장해 복원한다. 가장 큰 L을 가진 인덱스에서 시작해 prev를 따라가면 뒤에서 앞으로 수열을 얻으므로 마지막에 뒤집는다. 같은 길이를 주는 j가 여럿이면 어느 하나를 저장해도 한 최적 수열을 얻는다. 대본에서도 같은 길이를 주는 이전 인덱스 사이의 선택이 가능하다고 설명한다.

추가 확인용 예제인 `[3,1,2,5,4]`에서는 길이 표가 `[1,1,2,3,3]`이다. `1→2→5` 또는 `1→2→4`가 가능하다. 이는 원본 영상의 누락된 화면 배열을 복구한 것이 아니라 점화식을 확인하기 위한 별도 예제다.

### B-5. Box Stacking의 정확한 조건

상자는 각각 길이 l, 너비 w, 높이 h를 가진다. 위 상자의 길이와 너비가 아래 상자보다 **둘 다 엄격히 작아야** 한다. 높이는 쌓았을 때 더하는 값이며, 높이가 작다고 위에 놓을 수 있는 것은 아니다. 이 영상에서는 **상자를 회전시키지 않는다**. 회전이나 한 상자의 여러 방향 재사용을 허용하는 다른 버전과 섞지 않는다.

작은 밑면 상자에서 큰 밑면 상자로 간선을 그리면, 한 경로가 위에서 아래로 이어지는 한 스택을 뜻한다. 길이와 너비가 간선마다 증가하므로 사이클이 없다. 목표는 가장 많은 상자 수가 아니라 높이 합이 가장 큰 경로다. LIS에서 원소 하나당 1을 더하던 자리에 상자의 실제 높이를 더한다고 보면 구조가 연결된다.

### B-6. 바닥 상자를 고정하는 상태

`H[i]`는 상자 i를 맨 아래에 놓았을 때 만들 수 있는 최대 높이다. 위에 올릴 수 있는 상자 j는 `l_j<l_i`이고 `w_j<w_i`를 만족해야 한다. 그 위의 전체 최적 스택은 H[j]로 대표할 수 있다.

```text
H[i] = h_i + max(H[j] : l_j<l_i and w_j<w_i)
위에 올릴 후보가 없으면 H[i] = h_i
전체 답 = max_i H[i]
```

입력 순서가 임의라면 길이 오름차순 또는 너비 오름차순으로 먼저 정렬한다. 길이로 정렬했을 때 위에 올릴 수 있는 상자는 반드시 길이가 작으므로 먼저 처리된다. 다만 길이 정렬만으로 너비 조건까지 만족하는 것은 아니어서 두 조건 모두 검사한다. 길이가 같은 상자 사이에는 엄격 조건상 간선이 없으므로 순서가 같아도 문제가 없다.

영상은 각 상자를 키로 하는 dictionary를 사용하지만, 같은 치수의 상자가 입력될 때 별개의 객체가 합쳐질 수 있다. 학습용 일반 구현은 상자 인덱스별 리스트로 H를 저장하면 그 혼동을 피할 수 있다. 이 설명은 구현 보강이며 사용자 대본에 없던 실제 좌표·치수 데이터를 복원한 것은 아니다. 정렬 `O(n log n)`과 모든 앞 상자 비교 `O(n²)`를 합쳐 기본 구현은 `O(n²)` 시간, 상태 표는 `O(n)` 공간이다.

### B-7. 대본의 색상 예제 따라가기

대본은 첫 세 상자 예제의 최적 높이를 6으로, 여섯 상자 예제의 최적 높이를 7로 설명한다. 여섯 상자의 길이·너비·높이 전체 수치가 자막에 모두 있지는 않으므로 색상과 발화된 최적 상태를 기준으로 정리한다.

| 밑바닥으로 고정한 상자 | 대본에서 설명한 상태 |
| --- | --- |
| 보라 | 위에 올릴 수 있는 상자가 없어 H=2 |
| 주황 | 보라 위 스택을 사용할 수 있어 H=4 |
| 파랑 | 보라 위 스택을 사용할 수 있어 H=3 |
| 노랑 | 초록·보라·주황·파랑 후보 중 최고를 이용해 H=6 |
| 빨강 | 보라·주황·파랑 후보 중 주황의 H=4를 선택해 H=7 |

최종 스택은 아래부터 빨강·주황·보라이고 높이는 7이다. 노랑을 바닥으로 하는 높이 6의 해는 여러 방식이 있을 수 있다고도 말한다. 중요한 것은 상자들의 높이를 전부 더하는 것이 아니라 **바로 위의 후보 스택 중 최선 하나**를 선택하고 바닥 높이를 더한다는 점이다. 실제 스택 복원까지 원하면 선택된 위 상자의 인덱스를 저장해 따라가면 된다.

### B-8. 자주 쓰는 부분 문제의 형태

마지막 구간은 새 알고리즘 여러 개를 완성하는 시간이 아니라 상태를 찾을 때 살펴볼 후보를 분류한다. 한 수열에서는 prefix·suffix나 끝점을 고정한 상태를 생각할 수 있다. 상자처럼 입력 순서가 중요하지 않으면 먼저 적절히 정렬해 의존 순서를 만들 수도 있다. 두 수열이면 두 인덱스의 조합을 생각하고, 구간을 다루는 문제는 안쪽 구간에서 바깥으로 넓혀갈 수 있다. 행렬 문제라면 더 작은 부분행렬이나 좌표 상태가 후보가 된다.

대본의 느슨한 “길이 i의 subsequence”라는 말만 보고 LIS 상태를 모든 부분수열별로 만드는 것으로 오해하지 않는다. 이 영상의 실제 LIS 상태 수는 끝 인덱스별 n개다. 좋은 상태 정의는 가능한 답을 설명하는 데 필요한 정보만 남겨 상태 수를 제한한다. 어떤 문제에나 자동으로 통하는 고정 공식은 아니므로 예제에서 선택 조건을 직접 찾아보는 연습이 필요하다.

### C-2. SRTBOT과 local brute force

S는 Subproblems, R은 Relations, T는 Topological order, B는 Base cases, O는 Original problem, 마지막 T는 Time이다. 상태를 정의할 때는 자연어 의미와 인덱스 범위를 함께 쓴다. 이후 점화식의 모든 참조가 그 범위 안에 있는지 확인한다.

상태 후보는 수열의 prefix·suffix·substring, 정수 K보다 작은 정수들, 여러 축의 곱, 그래프 정점 등이다. 과거의 정보를 잊으면 다음 선택을 평가할 수 없는 경우에는 필요한 정보를 상태에 추가하는 subproblem expansion을 한다. 강의 초반 piano fingering과 Super Mario는 이런 상태 확장의 직관을 설명하는 짧은 회고·비유다. 이 대본에 두 문제의 명세나 완성된 알고리즘이 모두 제시되는 것은 아니다.

점화식은 “최적해의 어떤 선택 하나를 알면 더 작은 문제로 줄어드는가?”라는 질문에서 시작한다. Rod Cutting에서는 첫 조각 길이, Subset Sum에서는 현재 숫자를 포함하는지 여부를 물을 수 있다. 그 답을 마술처럼 맞히는 대신 가능한 답을 모두 비교한다. 이것이 local brute force다. 전체 해를 전부 나열하는 global brute force와 달리, 동일한 나머지 문제는 저장한 답을 재사용한다.

상태 수가 적어도 한 상태에서 비교할 선택지가 많으면 계산량이 커진다. 시간은 더 정확히는 **각 상태의 비재귀 작업량을 모두 합한 값**이고, 균일한 상한이 있을 때 상태 수×상태당 비용으로 쓴다. 실제 답을 여러 상태에서 뽑거나 복원할 비용도 필요하면 더한다. 숫자 연산을 상수로 세는 부분에는 값이 machine word에 들어간다는 계산 모델 가정이 있다.

### C-3. Rod Cutting: 문제와 greedy 반례

길이 L의 막대와 길이별 가격 `v[1..L]`이 주어진다. 조각 길이는 양의 정수이고 잘라내며 재료가 사라지지 않는다고 가정한다. 원래 문제는 막대 전체를 사용해 총 판매액을 최대로 만드는 것이다. 같은 길이의 조각이 여러 개 나와도 된다. 0-1 Knapsack처럼 입력 물건마다 한 번만 사용할 수 있는 문제가 아니다.

```text
조각 길이     1  2  3  4  5  6  7
가격 v       1 10 13 18 20 31 32
원래 길이 L = 7
```

단위 길이당 가격이 가장 좋은 길이 6부터 선택하면 `6+1`이고 판매액은 `31+1=32`다. 그대로 길이 7을 팔아도 32다. 그러나 `2+2+3`은 `10+10+13=33`으로 더 낫다. 따라서 `가격/길이`가 높은 조각을 먼저 고르는 greedy가 항상 최적이지 않다.

영상에서는 강사가 잠시 `3+4`를 제안했다가 `13+18=31`임을 확인하고 `3+2+2`로 정정한다. 자막의 중간 발언만 떼어 최적해가 `3+4`라고 보관하지 않는다. 길이별 가격은 단조 증가할 필요가 없고 음수일 수도 있다는 질문이 나온다. 다만 길이 0인 조각에 양의 가격을 허용하면 무한히 만들 수 있으므로 현재 문제에서는 조각 길이를 1 이상으로 제한한다.

### C-4. Rod Cutting을 SRTBOT으로 쓰기

| 항목 | 내용 |
| --- | --- |
| S | `R[l]`: 길이 l인 막대를 전부 나누어 팔 때 최대 판매액, `0≤l≤L` |
| R | `R[l]=max_{1≤p≤l}(v[p]+R[l-p])` |
| T | `l=1,2,...,L` 순서. 참조하는 `l-p`는 항상 l보다 작다 |
| B | `R[0]=0` |
| O | `R[L]` |
| T | 선택 수 합 `1+2+...+L=Θ(L²)`, 값 표는 `O(L)` 공간 |

한 상태에서 첫 조각 p를 선택하면 남은 길이는 l-p이다. 그 나머지를 최적으로 팔지 않으면 전체도 최적이 아니므로 R[l-p]를 사용한다. 모든 p를 비교하므로 실제 최적 분할의 첫 조각도 반드시 비교된다. p가 1 이상이라 재귀가 같은 l로 돌아오지 않으며 길이가 감소해 기저 조건에 도달한다. 이 논리로 길이에 대한 귀납 증명을 만들 수 있다.

```text
R[0] = 0
for l = 1..L:
    R[l] = -infinity
    for p = 1..l:
        if v[p] + R[l-p] > R[l]:
            R[l] = v[p] + R[l-p]
            first[l] = p
```

음수 가격이 가능하고 막대 전체를 팔아야 한다면 비어 있지 않은 상태의 최댓값 시작을 0으로 두지 않는다. 그 경우 최적값도 음수일 수 있기 때문이다. 일부를 안 팔아도 되는 변형에서는 max에 0을 추가할 수 있지만, 이는 원래 문제의 조건을 바꾼 것이다. 자르는 횟수에 따른 비용이나 톱날 손실도 현재 명세에 없으므로 멋대로 추가하지 않는다.

예제의 표는 `[0,1,10,13,20,23,31,33]`이다. 길이 4는 조각 2 두 개로 20, 길이 5는 2+3으로 23이다. `first[l]`을 저장하면 L에서 첫 조각을 출력하고 그 길이를 빼는 과정을 반복해 실제 분할을 복원할 수 있다. 동률이면 여러 최적 분할 중 하나를 얻는다.

### C-5. Rod Cutting의 DAG와 입력 크기

길이 0부터 L까지를 정점으로 두고, 길이 p를 추가하는 간선에 가격 v[p]를 붙이면, 0에서 L로 가는 경로가 하나의 분할을 나타낸다. 가격 합을 최대화하는 longest path를 DAG 순서로 구하는 문제로 볼 수 있다. 모든 간선 가중치를 음수로 바꾸면 shortest path 표현도 가능하다. 이것은 일반 그래프에서의 longest path가 쉽다는 주장이 아니다. 상태가 증가하는 DAG 구조이기 때문에 순서대로 풀 수 있는 것이다.

`Θ(L²)`가 왜 다항 시간인지 알려면 L이라는 기호만 보지 말고 실제 입력을 본다. 이 강의의 Rod Cutting은 정수 L 하나뿐 아니라 **길이 1부터 L까지의 가격 L개를 명시적으로** 받는다. 각 가격이 한 word에 들어간다고 할 때 입력은 `Θ(L)` words라서 L²은 입력 길이의 다항식이다. L이 숫자라는 이유만으로 이 알고리즘을 유사 다항 시간밖에 안 된다고 단정하면 안 된다. 뒤의 Subset Sum은 목표 T만 주어질 뿐 가격표처럼 T개의 입력이 주어지지 않아 분석이 달라진다.

### C-6. Subset Sum: 최적화가 아닌 결정 문제

숫자들의 multiset A와 목표 합 T가 주어진다. 그중 일부 원소를 골라 정확히 T를 만들 수 있는지 yes/no로 답한다. multiset은 같은 숫자가 여러 번 나올 수 있다는 뜻이다. 각 **입력 원소**는 한 번만 사용할 수 있지만 같은 값이 두 번 입력되면 서로 다른 두 원소로 골라도 된다. 입력을 정렬해야 한다는 조건은 없다.

대본의 예제 `A=[2,5,7,8,9]`에서는 T=21이면 `5+7+9`로 yes다. T=25는 no다. yes를 보이려면 구체적인 부분집합 하나를 제시하면 된다. no를 보일 때 숫자 몇 개를 시도해 실패했다는 것만으로 충분하지 않으며, 모든 가능성을 빠짐없이 고려하는 DP나 다른 근거가 필요하다. 강의의 짧은 복잡도 논의는 일반적인 no 인증의 어려움을 예고하는 것으로, 여기서 별도 복잡도 이론을 새로 완성하지는 않는다.

LCS·배낭은 길이나 이익의 max를 구했지만 Subset Sum은 가능한지 여부를 저장한다. 따라서 바깥 결합 연산은 max가 아니라 **OR**다. DP가 항상 최대·최소를 구하는 최적화 문제에만 쓰이는 것은 아니라는 예다.

### C-7. suffix × 남은 합의 상태

대본은 suffix 버전을 사용한다. `X(i,t)`는 `A[i..n-1]`의 원소들 중 일부로 합 t를 만들 수 있는지다. 범위는 `0≤i≤n`, `0≤t≤T`이다. 현재 원소를 쓰지 않으면 남은 목표는 t, 쓰면 t-a_i가 된다.

```text
미포함: X(i+1,t)
포함  : X(i+1,t-a_i)  단, a_i <= t

X(i,t) = X(i+1,t) OR (a_i <= t AND X(i+1,t-a_i))
```

두 경우 모두 i가 증가하므로 각 원소를 최대 한 번 쓴다. 목표 t만 상태로 두면 앞으로 어떤 원소가 남았는지 알 수 없어 같은 원소를 반복 사용하거나 필요한 선택을 놓칠 수 있다. 물건 범위를 기억하는 축과 수치 목표 축을 함께 두어야 한다는 점이 0-1 Knapsack과 같다.

이 강의는 입력 숫자가 **양의 정수**라는 가정을 후반 질문에서 명시한다. 음수가 있으면 t보다 큰 숫자가 나중에 음수로 상쇄될 수 있어 `a_i>t`라며 버리는 규칙이 안전하지 않다. 현재 상태 범위와 점화식을 그대로 음수 입력에 적용하지 않는다. 포함 분기는 `a_i≤t`일 때만 만들면 음수 t의 상태가 발생하지 않는다. 음수 t에 false를 주는 대체 설계도 가능하지만 상태 범위·기저 조건을 일관되게 다시 정해야 한다.

### C-8. 계산 순서·기저 조건·원래 답·복잡도

재귀 호출은 i+1을 참조하므로 bottom-up 순서는 **i=n에서 시작해 감소**시키는 것이다. t는 어떤 분기에서는 줄어들지 않으므로 t가 감소한다는 것만으로 위상 순서를 설명하면 불충분하다. 한 행을 계산할 때 참조하는 값은 모두 다음 행에 있어, 그 행 안의 t 순서는 자유롭다.

```text
X(n,0) = true
X(n,t) = false   (t>0)
전체 답 = X(0,T)
```

빈 suffix로 만들 수 있는 합은 0뿐이다. `X(n,t)`를 일반 점화식으로 계산하면 i=n+1을 참조하므로 이 행이 기저 조건이어야 한다. 상태는 `(n+1)(T+1)`개, 상태당 두 분기의 Boolean 결합은 word 연산 가정에서 상수다. 전체는 `O(n(T+1))`이며 n,T가 양수인 보통 표기에서는 `Θ(nT)`라고 쓴다. 전체 표의 공간도 `O(n(T+1))`이다. 모든 부분집합을 열거하는 지수 비용과 달리 같은 상태를 한 번만 계산한다.

### C-9. `[3,4,3,1]`, T=6 예제와 해 복원

```text
suffix 시작 i / 목표 t  0 1 2 3 4 5 6
i=4 : []               Y N N N N N N
i=3 : [1]              Y Y N N N N N
i=2 : [3,1]            Y Y N Y Y N N
i=1 : [4,3,1]          Y Y N Y Y Y N
i=0 : [3,4,3,1]        Y Y N Y Y Y Y
```

위 표는 대본의 예제를 점화식으로 다시 계산한 것이다. 원문 영상의 화살표 배치를 복사한 이미지는 아니다. `X(0,6)`이 yes인 경로는 첫 번째 3을 선택해 `(1,3)`, 4를 건너뛰어 `(2,3)`, 두 번째 3을 선택해 `(3,0)`, 1을 건너뛰어 `(4,0)`으로 간다. 마지막은 yes인 기저 조건이다. 서로 다른 위치의 3 두 개를 사용하므로 한 원소를 두 번 쓴 것이 아니다.

Boolean 표만 구해도 한 단계씩 참인 자식으로 이동하며 해를 복원할 수 있다. 부모·선택 포인터를 함께 저장하면 더 명확하다. 가능한 부분집합 전체를 모두 출력하라는 요청과 한 개를 찾으라는 요청은 다르다. 전부 출력해야 한다면 출력 자체가 지수적으로 커질 수 있어 같은 `O(nT)`만으로 전체 실행 시간을 보장하지 않는다.

### C-10. Pseudo-polynomial time: 값과 표현 길이

`O(nT)`에 곱셈만 보인다고 일반적인 다항 시간이라고 말하면 안 된다. T는 숫자 하나의 **값**이다. 이진수로 적는 데 필요한 길이는 `Θ(log(T+1))` bits다. b비트로 큰 목표를 적을 수 있어도 T가 `2^b` 수준이면 목표 0부터 T까지 표를 만드는 비용은 b에 대해 지수적일 수 있다.

예를 들어 목표 1,000,000을 적는 데 필요한 비트 수는 약 20이지만, DP 열은 약 백만 개다. 입력 원소 n개와 목표 하나가 주어진다는 사실은 백만 개의 입력 숫자가 있다는 뜻이 아니다. Rod Cutting은 길이별 가격을 L개 명시적으로 받는다는 점에서 다르다.

```text
다항 시간:
    입력의 표현 길이를 기준으로 다항식으로 제한됨

유사 다항 시간:
    입력 길이와 입력 정수의 수치 값에 대해서는 다항식이지만,
    이진 표현 길이만으로는 일반적인 다항 시간 보장이 안 됨

Subset Sum의 O(nT), 0-1 Knapsack의 O(nW):
    T나 W가 작은 경우 유용하지만, 수치가 크면 표가 매우 커짐
```

T가 n의 어떤 고정 다항식 이하라는 별도 제한이 있으면 nT도 n에 대한 다항식으로 제한된다. 그러나 그런 제한 없이 알고리즘 전체를 항상 다항 시간이라고 부르지는 않는다. “pseudo”는 답이 근사라는 뜻도 아니다. 이 DP는 조건에 맞게 계산하면 정확한 yes/no를 준다. 문제는 정답의 정확성이 아니라 수치 크기에 따른 실행 시간이다.

### C-11. Word-RAM과 강의의 다항 시간 용어

강의는 w비트 word를 가정하고, 입력 정수들이 한 word에 들어가는 조건에서 입력 words 수와 숫자의 크기를 비교한다. 메모리 인덱스를 표현하려면 보통 `w≥log n`이 필요하지만 이것은 w의 상한이 아니다. 따라서 그 가정만으로 `T≤poly(n)`이 따라오지 않는다. T가 크면 nT는 여전히 매우 커질 수 있다.

엄밀한 복잡도 용어에서는 일반적인 polynomial time은 이진 인코딩 전체 길이를 기준으로 설명한다. 강의는 숫자 값에 의존하지 않는 연산 수를 강조하며 strongly polynomial과 polynomial을 가깝게 부르는 부분이 있다. 그 단순화를 모든 계산 모델에서의 엄밀한 동의어로 외우지는 않는다. 현재 퀴즈의 핵심은 **숫자 값 T와 표현 길이 log T를 구분**하는 것이다.

정수의 저장·계산이 word를 여러 개 쓰게 되면 덧셈·비교도 무조건 O(1)이 아니다. 이 차이는 앞선 MIT Part 1의 Fibonacci `O(n+n²/w)`와 연결된다. 이번 Rod·Subset Sum의 표 연산 비용은 강의가 놓은 word 연산 가정하에서 센다.

### C-12. Counting·Direct Access·Radix Sort와의 연결

직접 접근 배열과 counting sort는 키 범위 u만큼의 배열을 만들거나 훑기 때문에 `O(n+u)` 같은 수치 의존성이 있다. u가 작으면 효과적이지만 u를 적는 데 필요한 길이에 비해 너무 커질 수 있다는 점이 유사 다항 시간의 직관과 같다. 강의는 이전 정렬 내용을 이 지점에 연결한다.

Radix sort는 base n에서 자릿수만큼 반복해 대략 `O(n(1+ceil(log_n u)))`가 된다. 정수 범위가 n의 고정 다항식이면 자릿수가 상수라 선형 시간이다. 큰 숫자 값 자체가 아니라 그 로그인 자릿수에 의존하는 것은 더 약한 수치 의존성이다. 강의는 이를 weakly polynomial이라는 용어와 연결하고 자세한 엄밀화는 뒤 과목의 주제로 남긴다. 새로운 radix sort 풀이를 요구한 구간이 아니라 입력 수치 의존성을 비교하는 구간이다.

| 상태의 형태 | 대본에서 회고하는 예제 | 분류의 의미 |
| --- | --- | --- |
| prefix / suffix | Bowling, LIS | 앞이나 뒤에서 일부를 떼어낸 뒤 남는 상태 |
| 두 수열의 prefix / suffix 곱 | LCS | 양쪽 수열의 현재 위치를 모두 기억 |
| substring / interval | Alternating Coins, Parenthesization | 양끝에서 줄이거나 중간을 나눠 생기는 구간 |
| 더 작은 정수 | Fibonacci, Rod Cutting | n이나 길이 l보다 작은 정수 상태 |

Rod Cutting은 길이 l로 생각할 수도 있고 가격표의 prefix를 쓰는 것으로 볼 수도 있다. 상태 정의에 표현 방법이 하나만 있는 것은 아니다. 중요한 것은 현재 정보로 다음 문제를 정확히 표현할 수 있고 상태 수·의존 관계를 분석할 수 있는가다.

### C-14. 후반부 전체 비교 2: 제약과 상태 확장

LIS에서 시작점 또는 끝점을 반드시 포함한다는 제약은 상태 의미를 더 구체적으로 만들지만 상태 개수를 여전히 O(n)으로 유지할 수 있다. 이를 강의는 non-expansive constraint로 설명한다. 단순히 제한을 추가했다고 무조건 상태 차원이 커지는 것은 아니다.

반대로 arithmetic parenthesization에서는 최댓값만으로 부족해 최솟값도 필요할 수 있으므로 min/max라는 두 상태를 둔다. alternating coin game에서는 누가 먼저 하는지에 따라 두 버전을 두는 예를 회고한다. piano·guitar fingering에서는 이전 손가락 배치 같은 과거 정보를 기억하도록 상태를 확장한다. Bellman-Ford에서는 최대 몇 개의 간선을 쓸 수 있는지를 추가해 한 정점당 여러 상태가 생긴다.

이 예들의 핵심은 미래의 최적 선택을 평가하는 데 필요한 과거 정보만 남긴다는 것이다. “상태를 많이 만들수록 정확하다”가 아니라 필요한 조건을 잃지 않으면서 가능한 한 작게 만드는 것이 목표다. 대본에 회고만 있는 예제의 세부 점화식을 새로 지어 강의에서 설명한 것으로 표시하지 않는다.

### C-15. 후반부 전체 비교 3: 분기·결합·원래 답

| 분류 | 대본의 예 | 시간 분석에서 볼 것 |
| --- | --- | --- |
| 상수 개 선택 | Fibonacci, Bowling, LCS, Alternating Coins, Floyd-Warshall, Subset Sum | 상태마다 몇 가지 정해진 분기만 계산 |
| 정점 차수만큼 선택 | DAG shortest paths, Bellman-Ford | 모든 상태에 걸쳐 간선을 검사하는 총비용 |
| 선형 개 선택 | LIS, Parenthesization, Rod Cutting | 후보 인덱스·분할점·조각 길이를 훑는 추가 비용 |

Rod Cutting의 상태 수가 O(L)이어도 첫 조각 후보가 O(L)이어서 총 O(L²)이다. LIS 역시 상태 n개지만 앞의 가능한 j를 모두 보아 기본 구현은 O(n²)이다. Subset Sum은 상태가 nT개로 많지만 각 상태는 포함·제외 두 선택만 보므로 O(nT)이다. “재귀 호출이 두 개니까 무조건 지수 시간”이라는 판단은 memoization으로 같은 상태가 재사용되는지 빠뜨린 것이다.

상태 답을 결합하는 방식도 다르다. LIS·Rod Cutting은 여러 후보 중 최선 하나를 선택하는 경로 관점이 자연스럽다. Subset Sum은 가능한 경로가 하나라도 있는지 OR한다. Fibonacci는 두 값을 더하고, Floyd-Warshall은 두 경로를 이어 붙이며, parenthesization은 양쪽 구간 답을 연산자로 결합한다. 이들은 모두 의존 DAG를 만들 수 있지만 모든 DP가 단순히 한 경로를 고르는 shortest path와 똑같지는 않다.

원래 답이 상태 하나인 경우도 있고 여러 상태를 비교해야 하는 경우도 있다. Rod Cutting은 R[L], Subset Sum은 X(0,T), LCS는 c[m,n]이다. LIS는 마지막 위치가 정해져 있지 않아 모든 끝점의 최댓값을 취해야 한다. 이 마지막 연결을 적지 않으면 상태를 잘 구해놓고도 다른 문제의 답을 반환할 수 있다.

### Q1. Rod Cutting

문제 원문:

Describe the dynamic programming algorithm to compute the Rod Cutting problem and analyze its time complexity.

사용자 제출 답안:

We use dynamic programming to find the maximum profit from cutting a rod. Let dp[i] be the maximum profit for a rod of length i. We start with dp[0] = 0. For each length i, we try all possible first cuts j from 1 to i. The recurrence is dp[i] = max(p[j] + dp[i-j]), where p[j] is the price of a rod of length j. We compute dp[1] to dp[n] using previous results. The time complexity is O(n^2) because we check up to n possible cuts for each rod length.

복습 연결: C-3~C-5. 답안의 n은 막대 길이를 뜻하며 강의에서는 L로 쓴다. 같은 알고리즘이다. 첫 조각 j가 i일 때는 막대 전체를 자르지 않고 파는 선택도 포함된다. 증명까지 요구되면 첫 조각을 기준으로 모든 최적 분할을 포괄한다는 논리와 남은 부분의 최적성을 추가한다.

### Q2. Subset Sum

문제 원문:

Describe the dynamic programming algorithm to compute the Subset Sum problem and analyze its time complexity.

사용자 제출 답안:

We use dynamic programming to check if some numbers in a given set can make the target sum S. Let dp[i][s] be true if we can make sum s using the first i numbers. We start with dp[0][0] = true and dp[0][s] = false for s > 0. For each number a[i], we can either include it or exclude it. The recurrence is dp[i][s] = dp[i-1][s] OR dp[i-1][s-a[i]] when s >= a[i]. Otherwise, dp[i][s] = dp[i-1][s]. The final answer is dp[n][S]. The time complexity is O(nS), where n is the number of elements and S is the target sum.

복습 연결: C-6~C-9. 이 답안은 첫 i개를 쓰는 **prefix 버전**, 영상은 i부터 남은 원소를 쓰는 **suffix 버전**이다. 둘 다 올바른 상태 설계이며 기저 행·계산 순서·최종 위치를 일관되게 쓰면 된다. prefix는 i를 증가시키고 suffix는 감소시킨다. 양수 입력 가정하에 목표를 넘는 포함 분기를 제외한다. 수치 축 하나로 공간을 줄이는 구현도 가능하지만, 그때는 이전 물건 단계만 반영하도록 합을 순회하는 방향까지 설계해야 한다. 단계 관리 없이 목표 하나만 남기면 같은 원소를 중복 사용하는 다른 문제가 될 수 있다.

### Q3. Pseudo-polynomial time

문제 원문:

Explain what is meant by an algorithm having pseudo-polynomial time.

사용자 제출 답안:

An algorithm has pseudo-polynomial time when its running time is polynomial in the numeric values of the input, but not necessarily in the input size measured in bits. For example, the dynamic programming algorithm for Subset Sum takes O(nS) time. However, the number S needs only O(log S) bits to represent in binary. Therefore, O(nS) is pseudo-polynomial time because it depends on the value of S, not just the number of bits needed to represent S.

복습 연결: C-10~C-12. 핵심은 수치 값과 표현 길이의 구분이다. S=0도 포함해 엄밀히 쓰려면 비트 수를 `O(1+log(S+1))`로 표현한다. 현재 문제에서 양의 큰 목표를 설명하는 일반적인 문맥에서는 답안의 `log S` 표기를 이해할 수 있다. 채점 결과가 나오지 않았으므로 이 문서에서 점수를 임의로 확정하지 않는다.

| 0-1 배낭 | 첫 i개·용량 c의 최대 이익 | 제외 / 포함 후 이전 행의 남은 용량 | i 증가, V[n,M] | O(nM), 수치 M에 의존 |
| 배낭 Sets Method | 단계별 (이익,무게) 후보 | 미포함·포함 병합, 초과·지배 후보 제거 | 물건별 단계 증가, 최종 최고 이익 | 후보 수에 의존, 무조건 작은 다항식으로 단정 금지 |
| LIS | i에서 끝나는 최대 길이 L[i] | 유효한 이전 j의 max+1 | i 증가, max L[i] | 기본 O(n²) |
| 상자 쌓기 | i를 바닥으로 하는 최대 높이 H[i] | 올릴 수 있는 j의 최고 스택+h_i | 한 밑면 축 정렬 후, max H[i] | 기본 O(n²) |
| Rod Cutting | 길이 l 전체의 최대 판매액 R[l] | 모든 첫 조각 p를 비교 | l 증가, R[L] | Θ(L²), 명시 가격표 기준 다항 시간 |
| Subset Sum | suffix i와 목표 t의 가능 여부 X(i,t) | 미포함 OR 포함 | i 감소, X(0,T) | Θ(nT), 유사 다항 시간 |

실제로 설명할 수 있는지 다음 순서로 확인한다. 먼저 상태의 뜻과 입력 조건을 한 문장으로 쓴다. 이어 최적해 또는 가능한 해의 마지막·첫 선택을 기준으로 빠짐없는 경우를 나눈다. 그 선택을 고정하면 나머지가 어떤 상태인지 적는다. 기저 조건을 적고 모든 참조가 먼저 계산되는 이유를 설명한다. 마지막으로 원래 답과 실제 해 복원을 구분하고 상태 수와 상태당 비용을 계산한다.

- LCS: 길이와 부분수열 자체를 모두 구할 수 있는가? 두 인덱스 표기와 빈 문자열 경계를 일관되게 쓰는가?
- 배낭: 같은 물건 중복 사용을 이전 행 참조로 막는 이유를 설명하는가? 최대 이익 8과 선택 `[0,1,0,1]`을 둘 다 복원하는가?
- Sets Method: 용량 초과 제거와 dominance 제거를 구분하는가? 후보 쌍의 순서를 (이익,무게)로 일관되게 쓰는가?
- LIS: 배열 정렬 없이 인덱스 순서를 보존하는가? 전체 답이 마지막 상태가 아니라 max라는 것을 아는가?
- 상자: 회전 불가, 두 밑면의 엄격 부등식, 높이 합이라는 조건을 모두 반영하는가?
- Rod Cutting: 비율 greedy의 32와 DP의 33을 비교하는가? 첫 조각 전체 길이 선택과 음수 이익 조건을 놓치지 않는가?
- Subset Sum: 동일 값의 서로 다른 원소를 구분하는가? 포함 분기의 범위·Boolean OR·prefix/suffix 순서를 정확히 쓰는가?
- 유사 다항 시간: `O(nT)`라는 식만 보고 polynomial이라고 하지 않고 T의 비트 길이를 설명하는가?

## 원문과 정리본의 차이 및 검수 범위

이번 정리는 **세 첨부 대본 전체를 읽고** 시간대별 본문·예제·질의응답·마지막 분류까지 재구성했다. Knapsack 표와 후보 집합, Rod Cutting의 길이별 최적값, Subset Sum 예제 표는 점화식으로 독립 계산해 숫자를 대조했다. 채널 구독·마무리 발언은 원문에 그대로 남기고 학습 개념으로 늘려 쓰지 않았다.

자동 자막의 `napsack/Absa`, `swordbot/sort bot`, `memorization`, `subproblem tag`, `weekly polynomial` 등은 문맥에 따라 Knapsack, SRTBOT, memoization, subproblem DAG, weakly polynomial로 바로잡았다. 원문 파일 자체는 고치지 않았다. 강사의 Rod Cutting 중간 계산 정정, 배낭 후보가 “틀렸다”는 느슨한 표현, 원문의 일부 음성 오인식은 검증된 수식·논리와 구분해 위에서 설명했다.

이번에는 영상 자체의 모든 프레임·판서를 눈으로 검수한 것이 아니다. 따라서 자막에 없는 LIS 전체 입력 배열, 모든 상자의 치수, 판서 코드의 실제 문장까지 복원했다고 주장하지 않는다. 대본으로 확인 가능한 내용은 교안에 반영하고, 필요한 의사코드·증명·숫자 표는 재구성임을 표시했다. 교수님 PDF는 이전 대조에서 전체 텍스트와 주요 수식·예제 페이지를 확인한 범위로 연결했다. 이 문서는 그 PDF 모든 페이지의 전문 OCR 결과가 아니다.

사용자가 준 영상 세 개와 퀴즈 DP 2 외에 새로운 PA나 영상이 없다고 단정하지 않는다. 향후 iCampus 목록이 추가되면 출처별로 붙인다. MIT 후반부가 언급하는 다른 강의의 회고를 근거로 그 강의 전체가 우리 과목의 새 필수 범위라고 표시하지 않는다. 자료 정리 완료와 사용자 수강·개념 학습 완료도 별개로 유지한다.
