### 프로그래밍 과제 계획

프로그래밍 과제는 RISC-V simulator를 만드는 방향으로 계획되어 있습니다. simulator는 RISC-V CPU의 동작을 소프트웨어로 흉내 내는 프로그램입니다. 과제는 여러 단계로 나뉘며, 과제가 진행될수록 simulator에 기능을 계속 추가하는 방식으로 보입니다.

중요한 안내는 “한 과제를 실패하면 다음 과제를 완료하기 어려워질 수 있다”는 점입니다. 즉 PA는 독립 숙제라기보다 누적형 프로젝트입니다. 첫 과제부터 코드 구조, 테스트, 문서화를 안정적으로 가져가는 것이 중요합니다. 세부 사항은 TBA로 되어 있으므로 아직 확정 공지는 기다려야 합니다.

중간부터는 컴퓨터구조의 큰 그림입니다. 왜 RISC-V를 기준으로 배우는지 설명합니다. x86은 실제 시장에서 매우 중요하지만 복잡하고, ARM도 많이 쓰이지만 기본 원리를 설명하기에는 RISC-V보다 조금 더 복잡하며 ISA가 자유롭지 않다고 설명합니다. RISC-V는 open standard이고 구현체가 많으며 reduced instruction set이라 수업용으로 적합합니다.

이후에는 컴퓨터의 종류를 소개합니다. 개인용 컴퓨터는 범용성과 사람과의 상호작용이 중요하고, 서버는 용량과 신뢰성이 중요하며, 슈퍼컴퓨터는 계산 성능에 특화됩니다. 임베디드 컴퓨터는 자동차나 가전처럼 다른 시스템 안에 들어가며 크기, 전력, 성능 제한이 큽니다. 이 구분은 “컴퓨터”라는 단어가 하나의 물건이 아니라 목적에 따라 다른 설계 선택을 갖는다는 점을 보여줍니다.

후반부는 컴퓨터구조의 7가지 큰 아이디어와 하드웨어 추상화입니다. 추상화, common case 최적화, 병렬성, 파이프라이닝, 예측, 메모리 계층, 중복을 통한 신뢰성이 앞으로 수업 전체를 관통하는 키워드입니다. 마지막에는 ISA/ABI, high-level language, assembly language, machine code, datapath, control, registers, cache, DRAM 같은 단어가 등장합니다. 이 단어들은 앞으로 Chapter 2, 4, 5에서 계속 구체화됩니다.

## 1주차 개념 지도

### 1. 컴퓨터구조의 목표

컴퓨터구조는 하드웨어와 소프트웨어 사이의 관계를 이해하는 과목입니다. 프로그래머가 작성한 고급언어 코드는 컴파일과 변환을 거쳐 기계어가 되고, CPU는 명령어를 해석해 datapath와 control을 통해 데이터를 이동시키고 계산합니다. 이 흐름을 이해하면 프로그램 성능이 왜 달라지는지, 어떤 코드가 하드웨어에 부담을 주는지, 왜 메모리 접근이 중요한지 볼 수 있습니다.

### 2. 추상화

컴퓨터 시스템은 너무 복잡해서 모든 세부사항을 한 번에 볼 수 없습니다. 그래서 추상화가 필요합니다. 애플리케이션, 프로그래밍 언어, 기계어, 프로세서 구조, 마이크로아키텍처, 회로, 반도체 같은 계층으로 나누면 각 단계에서 중요한 것만 볼 수 있습니다. 추상화는 세부사항을 숨겨 모델을 단순하게 만드는 방법입니다.

이 수업에서는 특히 하드웨어/소프트웨어 인터페이스를 중요하게 봅니다. 소프트웨어는 하드웨어를 직접 만지는 것이 아니라 ISA 같은 약속을 통해 하드웨어를 사용합니다. ISA를 이해하면 프로그램과 CPU 사이의 계약을 이해하는 셈입니다.

### 3. RISC-V를 쓰는 이유

현대 x86 컴퓨터는 매우 복잡합니다. 오래된 소프트웨어와의 호환성을 지키면서 발전했기 때문에 명령어 집합도 복잡합니다. 반대로 RISC-V는 open standard이고 단순한 reduced instruction set을 기반으로 합니다. 그래서 실제 산업에서도 의미가 있으면서, 수업에서 CPU 동작 원리를 설명하기에 좋습니다.

RISC-V 컴퓨터가 없어도 simulator로 RISC-V 소프트웨어를 테스트할 수 있습니다. 이 점은 PA 계획과 연결됩니다. 이 과목의 프로그래밍 과제는 RISC-V CPU의 행동을 흉내 내는 simulator를 단계적으로 만드는 방향입니다.

### 4. x86과 backward compatibility

x86은 Intel과 AMD의 프로세서 계열을 가리키며, 8086, 80286, 80386, 80486 같은 초기 모델 번호에서 이름이 이어졌습니다. x86-16, x86-32, x86-64처럼 발전해왔고, 시장 지배력을 유지한 중요한 이유 중 하나는 legacy software와의 backward compatibility입니다.

하지만 호환성을 오래 유지한다는 것은 복잡성을 떠안는다는 뜻이기도 합니다. 이 대비를 통해 왜 수업에서는 더 단순한 RISC-V를 중심으로 배우는지 이해할 수 있습니다.

### 5. 컴퓨터의 종류

개인용 컴퓨터는 범용 작업과 사람의 상호작용을 중심으로 합니다. 서버는 높은 용량과 신뢰성을 중시합니다. 슈퍼컴퓨터는 과학 실험, 날씨 예측 같은 대규모 계산 성능에 특화됩니다. 임베디드 컴퓨터는 자동차, 가전, 통신장비처럼 다른 시스템 안에 들어가며 전력, 크기, 비용 제약이 큽니다.

이 분류는 컴퓨터구조 설계가 항상 목적과 제약을 따라 달라진다는 점을 보여줍니다. 같은 CPU 원리를 배워도, 서버와 임베디드 시스템에서 중요한 최적화 기준은 다를 수 있습니다.

### 6. Post-PC 시대와 클라우드

Post-PC era에서는 스마트폰, 태블릿, 전자 안경 같은 개인 모바일 장치가 중요해집니다. 이런 장치는 배터리로 동작하고 인터넷에 연결되며, 가격과 전력 제약을 가집니다. 동시에 cloud computing은 저장과 계산이 특정 기기 안에만 묶이지 않게 합니다.

예를 들어 모바일 기기에서 찍은 사진을 클라우드에 저장하거나, 복잡한 계산을 강력한 서버에 요청하거나, 직접 서버를 관리하지 않고 클라우드 기반 가상머신을 사용하는 식입니다. 이 흐름은 컴퓨터구조가 단일 CPU만이 아니라 네트워크와 데이터센터 환경까지 연결된다는 것을 보여줍니다.

### 7. Seven Great Ideas in Computer Architecture

Chapter 1의 중요한 목차입니다.

- Use abstraction to simplify design
- Make the common case fast
- Performance via parallelism
- Performance via pipelining
- Performance via prediction
- Hierarchy of memories
- Dependability via redundancy

이 7가지는 세부 단원이 아니라 앞으로 계속 반복되는 설계 원칙입니다. 예를 들어 파이프라이닝은 Chapter 4에서 본격적으로 다루고, memory hierarchy는 Chapter 5의 중심 주제가 됩니다. common case fast는 성능 최적화의 기본 태도이고, redundancy는 시스템 신뢰성을 높이는 방식입니다.

### 8. Make the common case fast

자주 일어나는 경우를 빠르게 만드는 것이 드문 경우를 과도하게 최적화하는 것보다 효과적일 때가 많습니다. 일반적으로 common case는 rare case보다 단순한 경우가 많고, 실제 성능에 미치는 영향도 큽니다. 알고리즘에서도 평균적으로 자주 만나는 입력을 고려하듯, 컴퓨터구조에서도 자주 쓰는 명령, 자주 접근하는 데이터, 자주 발생하는 실행 패턴이 중요합니다.

### 9. Parallelism과 pipelining

Parallelism은 여러 일을 동시에 수행해 성능을 높이는 아이디어입니다. Pipelining은 작업을 여러 단계로 나누고, 각 단계가 서로 다른 일을 겹쳐 수행하게 만드는 방식입니다. 세탁, 조립라인, CPU 명령어 처리처럼 한 작업이 끝날 때까지 기다리지 않고 다음 작업을 밀어 넣는 구조를 떠올리면 됩니다.

이번 자료에서는 개념 맛보기만 나오지만, 뒤 주차에서는 datapath와 control, pipelined datapath, hazards와 연결됩니다. 특히 pipeline hazards는 명령어들이 겹쳐 실행될 때 생기는 충돌과 지연 문제를 다루는 핵심 주제입니다.

### 10. Prediction

예측은 앞으로 어떤 작업을 해야 할지 미리 판단해서 성능을 높이는 방법입니다. 예측이 맞으면 기다리는 시간을 줄일 수 있지만, 틀리면 하던 일을 취소하고 다시 해야 합니다. CPU에서는 branch prediction 같은 형태로 매우 중요해집니다. 자료의 예시는 A/B 중 어떤 일을 해야 하는지 예측했을 때 맞는 경우와 틀린 경우의 차이를 보여줍니다.

### 11. Memory hierarchy

빠르고 큰 메모리는 만들기 어렵거나 비쌉니다. 그래서 컴퓨터는 작고 빠른 메모리와 크고 느린 메모리를 계층적으로 배치합니다. 자주 접근하는 데이터는 빠른 쪽에 두고, 드물게 접근하는 데이터는 느리고 큰 쪽에 둡니다. 캐시와 DRAM의 관계가 대표적입니다.

이번 주차에서는 개념만 나오지만, Week 12-14에서 memory hierarchy를 본격적으로 다룰 예정입니다. 프로그램 성능에서 메모리 접근 패턴이 중요한 이유가 여기서 시작됩니다.

### 12. Dependability via redundancy

신뢰성을 높이기 위해 중복을 사용할 수 있습니다. 같은 계산을 여러 장치에서 수행하거나, 같은 데이터를 여러 곳에 저장해 하나가 틀리거나 고장 나도 전체 결과를 판단할 수 있게 하는 방식입니다. 자료의 예시는 여러 결과 중 하나가 다를 때 문제가 있음을 감지하고, 다수결처럼 더 그럴듯한 결과를 선택하는 흐름을 보여줍니다.

### 13. ISA와 ABI

ISA는 Instruction Set Architecture의 약자입니다. 소프트웨어가 하드웨어를 추상화해서 바라보는 방식이며, 하드웨어/소프트웨어 인터페이스입니다. CPU가 어떤 명령을 이해하고, 그 명령이 어떤 의미를 가지며, 프로그램이 하드웨어를 어떻게 사용할 수 있는지를 정합니다.

ABI는 Application Binary Interface입니다. ISA에 운영체제와 시스템 소프트웨어 인터페이스까지 더한 실행 환경의 약속으로 볼 수 있습니다. 예를 들어 x86 Windows 애플리케이션과 ARM iOS 애플리케이션은 서로 다른 ABI 환경 위에서 동작합니다.

### 14. 프로그램 코드의 계층

고급언어는 문제 영역에 가까운 추상화 수준을 제공합니다. 그래서 생산성과 이식성이 좋습니다. 어셈블리 언어는 CPU 명령어를 사람이 읽을 수 있는 형태로 표현합니다. 기계어는 명령어가 하드웨어 안에 실제로 저장되고 실행되는 형태입니다.

컴퓨터구조에서는 이 계층을 오가게 됩니다. C/C++ 코드가 어떤 어셈블리로 바뀌고, 그 명령어가 CPU 내부에서 어떻게 처리되는지를 이해하는 것이 뒤 단원의 중요한 목표가 됩니다.

### 15. CPU 내부 구성

CPU 내부에는 datapath, control, registers, cache가 등장합니다. Datapath는 데이터가 구성요소 사이를 이동하며 계산되는 경로입니다. Control은 각 구성요소가 언제 무엇을 해야 하는지 지시합니다. Register는 CPU 안의 임시 저장공간이고, cache는 자주 접근하는 데이터를 CPU 가까이에 둬서 메모리 접근 비용을 줄입니다. DRAM은 프로그램 실행 중 주요 데이터를 저장하는 main memory입니다.

이번 자료에서는 내부 구성도를 간단히 보여주고, 뒤에서 processor architecture와 실제 프로세서 사진으로 이어집니다. 지금 단계에서는 세부 구현보다 용어와 큰 관계를 잡는 것이 중요합니다.
