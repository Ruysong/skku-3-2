# xv6 PA3 — 가상메모리 구현 범위와 근거

근거: [제출 보고서](./PA3_Report_2024315329_Junhyuk_Song.pdf), [과제 명세](./Project%203_26f.pdf), [제출 기록](../../assignments.md). 보고서 3쪽을 2026-11-17 대조했다. 최종 서버 소스는 현재 공개 저장소에 보관되지 않았고, 이번 문서 작업에서 QEMU를 재실행하지 않았다.

## 수행한 과제

xv6의 기존 시스템콜·스케줄링 과제 코드를 유지하면서 `mmap`, `munmap`, `freemem`과 page fault 처리를 연결한 교육용 커널 확장이다.

| 구현 영역 | 보고서의 설명 |
|---|---|
| 시스템콜 진입 | syscall 번호·table·user stub·인자 처리 연결 |
| 매핑 관리 | 전역 mmap_area 64개, 소유 프로세스·주소·길이·권한·flags·파일 참조 |
| eager/lazy | MAP_POPULATE는 즉시 페이지 할당, 그 외에는 접근 시 fault에서 한 페이지 할당 |
| 파일 매핑 | filedup으로 매핑 수명 유지, inode readi로 해당 offset 읽기 |
| 권한 | 사용자 PTE, 쓰기 권한, fault error의 쓰기 접근 검사 |
| munmap | 존재하는 PTE만 해제, 비어 있는 page table 정리, TLB 갱신·fileclose |
| freemem | freelist의 물리 페이지 수를 잠금으로 관리 |
| fork | 이미 할당된 물리 페이지 공유·참조 수 증가, 미할당 lazy 영역은 정보 상속 |
| 종료·회수 | exit에서 매핑 기록·파일 참조 정리, wait/freevm에서 페이지와 참조 수 처리 |

```text
mmap 요청 → 인자·권한 검사 → 영역 기록
                           ├─ eager → 페이지 할당·파일 초기화·PTE
                           └─ lazy  → 접근 시 page fault → 권한 확인 → 한 페이지 할당
fork → 기존 페이지 공유·참조 수 증가
munmap / exit·wait → PTE·페이지·파일 참조 회수
```

## 확인 결과의 범위

- 보고서의 자체 통합 시험 결과는 **30 PASS, 0 FAIL**이다. 사용자도 당시 테스트 통과와 제출 완료를 확인했다.
- 시험 항목: 익명 eager/lazy, 페이지 0 초기화·해제 후 free count, 파일 내용·offset·fd 종료 후 매핑 유지, fork 공유와 미할당 영역, 읽기 전용 쓰기·반환값.
- PDF 제출은 11/16 iCampus API에서 확인했고 코드 서버 제출은 사용자·제출 로그 확인이다. [과제 관리](../../assignments.md)에서 확인한다.
- 공식 채점 점수, 모든 숨은 입력의 성공, 현재 최종 코드에 대한 새 실행 검증은 뜻하지 않는다. 파일 변경의 디스크 write-back은 보고서에서 구현 범위에 포함하지 않았다.

## 면접에서 설명할 연결

1. 예약한 가상 주소 공간과 실제 할당된 페이지의 차이.
2. lazy fault를 해결할 수 있는 경우와 권한 위반을 종료하는 경우.
3. fd를 닫아도 매핑이 유지되는 이유와 file 참조 수.
4. 부모가 munmap해도 자식의 공유 페이지가 살아 있는 이유.
5. exit와 wait 사이에서 기록·파일·물리 페이지가 해제되는 시점.

이 설명은 보고서 기반 학습 지도다. 실제 수정 코드를 확보하면 함수·잠금 범위·실패 경로를 코드와 대조한다.
