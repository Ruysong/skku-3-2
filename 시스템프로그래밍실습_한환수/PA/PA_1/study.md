# PA1 구현 교안: Unix I/O 파일 검색기

## 전체 구조

```text
argv filename -> open(O_RDONLY) -> fd
                                      |
stdin -> read_query() -> query         |
             |                        |
         PA1EXIT? -> stop              |
             |                        |
         lseek(fd, 0, SEEK_SET) -------+
             |
         classify query
             |
  +----------+----------+----------+----------+
  | one word | all words| phrase   | pattern  |
  +----------+----------+----------+----------+
             |
       read file chunks
             |
       assemble one line -> line matcher
             |
       output buffer -> write_all(stdout)
```

검색마다 파일 전체를 다시 읽는 구조다. 이전 검색의 fd 위치가 EOF에 있으므로 `lseek`으로 시작 위치를 되돌린다. 한 번 읽은 파일 전체를 메모리에 올린 뒤 모든 질의에 재사용하는 인덱스 시스템은 아니다.

## 질의 분류와 파일 위치

실제 분기 순서는 다음과 같다.

```text
contains '*' ?             -> search_pattern
else starts/ends with '"'? -> search_phrase (양끝 따옴표 제외)
else contains ' ' ?        -> search_multi_words
else                      -> search_one_word
```

`PA1EXIT`은 길이 7과 문자 전체가 정확히 맞을 때 종료한다. EOF도 종료 조건이다. 입력 읽기나 검색이 실패하면 파일을 닫고 오류 종료한다. 파일을 질의마다 다시 open하는 대신, 이미 열린 fd를 `lseek`으로 되돌린다.

질의 종류와 “한 줄에서 match가 성립하는가”는 다른 책임이다. main은 어떤 함수가 실행될지 결정하고, line matcher는 그 질의에 맞는 비교 규칙을 적용한다.

## 입력 버퍼와 줄 조립

`read_query()`는 8,192바이트 stdin 버퍼를 사용하며, 한 번의 read에 여러 질의가 들어오면 다음 호출에서 남은 바이트를 이어 사용한다. 질의 저장 배열은 최대 4,096문자와 종료문자 공간이다. newline이 질의를 끝내고, 마지막 질의의 EOF도 처리한다. read가 `EINTR`로 중단된 경우 재시도한다. CRLF 입력의 끝 CR은 제거한다.

파일 검색은 65,536바이트 chunk를 읽는다. read chunk의 끝이 텍스트 줄의 끝이라는 보장은 없다. `LineBuffer`는 초기 용량 128에서 필요할 때 두 배로 늘어나며, newline을 볼 때까지 여러 chunk의 문자를 이어 담는다.

```text
read #1: ... [a long li
read #2: ne continues ... \n next ...]
                |
         one logical line
```

newline을 만나면 완성된 줄에 검색을 적용하고 버퍼 길이를 비운다. 줄 번호는 1부터 증가한다. 마지막 줄에 newline이 없어도 남은 내용이 있으면 검색한다. 줄 끝 CR을 제거하는 것과 줄 **내부** CR을 단어 구분자로 인정하는 것은 별개의 동작이다.

## 네 검색의 실제 동작

### 1. 단일 단어

`search_one_word()`가 파일을 읽고 `search_line()`이 한 줄을 검사한다. ASCII 대소문자는 `lower_ascii()`로 통일해 비교한다. 전체 token 길이까지 같아야 하므로 부분 문자열 검색과 다르다. 한 줄에서 여러 번 나오면 각각의 `line:start`를 출력한다.

`line`은 1-based, `start`는 그 줄의 0-based byte 위치다. UTF-8 문자의 화면상 글자 수와 byte offset이 항상 같다고 생각하면 안 된다. 현재 비교 로직은 ASCII 대소문자 변환이다.

### 2. 여러 단어

`search_multi_words()`는 질의의 space 구분 단어들을 만든 뒤 `search_multi_line()`에서 각각이 현재 줄에 존재하는지 `contains_word()`로 확인한다. 모든 단어가 있으면 줄 번호를 한 번 출력한다. 질의 단어가 줄에서 같은 순서로 나타나야 한다는 조건은 없다. 단어 하나가 줄에 여러 번 나와도 이 모드의 줄 번호 출력은 한 번이다.

### 3. 따옴표 phrase

`search_phrase()`는 양끝 따옴표를 제거한 질의를 받는다. `search_phrase_line()`은 대소문자를 무시하며 연속한 문자열이 맞고 시작·끝이 token 경계인지 확인한다. 내부 space는 문자열의 일부다. 여러 단어가 떨어져 있어도 되는 2번 검색과 다르다. 일치한 모든 시작 위치를 출력한다.

### 4. word1*word2 pattern

`search_pattern()`은 `*` 앞뒤의 두 단어를 구분하고, `search_pattern_line()`은 첫 단어가 나온 뒤 같은 줄의 뒤쪽에 두 번째 단어가 나오는지 검사한다. 두 단어의 순서가 중요하다. match가 하나 이상 있으면 줄 번호는 한 번만 출력한다.

과제 PDF 6페이지는 두 단어 사이에 **0개 이상의 단어**가 올 수 있다고 설명한다. 따라서 인접한 두 단어도 허용하는 현재 동작은 이 조건과 일치한다. 두 단어 사이에 반드시 다른 단어가 하나 있어야 한다고 잘못 기록하지 않는다.

## 출력과 복잡도

출력은 `printf` 대신 `write`를 사용한다. `append_number()`는 숫자의 10진수 문자를 직접 만든다. `emit_match()`는 위치 형식을 조립하고, `output_write()`·`output_flush()`는 65,536바이트 출력 버퍼를 관리한다. `write_all()`은 partial write가 발생하면 아직 못 쓴 나머지를 계속 쓰고 `EINTR`도 처리한다.

결과 사이에는 공백, 질의 사이에는 newline이 들어간다. 검색 결과가 없어도 빈 한 줄을 출력하므로 입력 질의와 출력 줄의 대응이 유지된다. 위치 모드는 모든 출현, 줄 번호 모드는 한 줄에 한 번만 출력한다.

파일 길이 B, 질의 길이 L, 여러 단어 질의의 단어 수 k라 하면 파일 I/O 자체는 검색마다 `O(B)`다. 다만 phrase의 후보 위치별 문자 비교는 최악에 `O(BL)`, 여러 단어를 각각 찾는 방식은 비교 비용을 포함해 k에 따라 증가한다. 모든 검색이 질의 길이와 무관한 무조건 `O(B)`라고 단정하지 않는다.

메모리는 파일 전체가 아니라 현재 한 줄의 길이와 질의, 고정 입출력 버퍼에 비례한다. 아주 긴 한 줄이면 LineBuffer도 그 길이만큼 커진다. 줄을 처리하고 clear해도 확보된 capacity는 이후 줄에 재사용된다.

## 요구사항과 실제 구현의 차이

| 항목 | 실제 소스 | 확인 결론 |
| --- | --- | --- |
| `stdio.h` 사용 금지 | Unix I/O와 자체 숫자 출력 사용 | 해당 제한에 맞는 방향 |
| ASCII 대소문자 무시 | `lower_ascii` 비교 | 구현됨 |
| punctuation 포함 token | 경계를 찾고 token 전체 비교 | `word`와 `word.`를 같은 단어로 합치지 않음 |
| pattern 사이 0개 이상 단어 | 앞 단어 이후 뒤 단어 검사 | PDF 6페이지 설명과 일치 |
| LF 줄, CRLF 끝 CR | newline 처리 및 끝 CR 제거 | 구현됨 |
| 단어 구분에 `\t`, `\r` 포함 | token 및 질의 분류에 `' '` 검사만 사용 | **추가 Q&A 요구와 차이 있음** |

마지막 항목은 시험해 보지 않아도 소스에서 확인되는 제약이다. `word1\tword2`처럼 tab으로 구분된 입력은 두 단어로 나누지 못할 수 있다. 줄 내부의 `\r`도 일반 경계로 처리하지 않는다. CRLF의 마지막 CR을 제거한다고 이 요구가 충족되지는 않는다.

이는 감점 확정 통보가 아니라 **제출 압축본과 추가 안내 사이의 차이** 기록이다. 채점 입력에 실제로 이 사례가 있었는지, 점수가 어떻게 나왔는지는 확인하지 않았다. 제출된 코드를 몰래 수정하거나 수정본을 최종 제출본처럼 보관하지 않았다.

이번 점검은 소스·압축본 대조이며 새 Linux 실행 테스트는 수행하지 않았다. 공식 examples의 예상 출력과 실제 실행 결과는 별도 비교가 필요하다.
