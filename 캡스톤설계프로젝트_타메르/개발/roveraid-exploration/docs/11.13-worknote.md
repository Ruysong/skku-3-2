# 11.13 · 노트북 인식·임무 판단 계층 개발

## 추가 구현 · 텍스트 우선 판단과 부분 신체 단서

아래 초기 구조 이후 기본 AI 입력을 사진에서 관측 텍스트로 변경했다. 최신 동작은 이 추가 기록과 README를 기준으로 확인한다.

```text
YOLO 사람 검출·Pose 관절 추정
  → 관절 근거 / 화면 좌우 / 부분 신체 단서
  → 잠깐 보인 단서 기억 / 반복 관측·미확정 구분
  → 새로운 사건에서 텍스트 AI 판단
  → 재관측 요청 생성 (실제 회전·접근은 별도 어댑터)
```

- 무릎·발목 등 하체 관절에 근거가 있고 상체 관절 근거가 부족하면 lower_body_hint로 기록한다. 모델이 사람 자체를 검출하지 못하면 단서도 만들 수 없다.
- 강한 한 번의 하체 단서는 미확정 사건으로 보존하고, 반복 관측이면 별도로 구분한다. 추적 ID가 없는 검출도 임시 후보로 남긴다.
- 최근 단서를 최대 15초 보관하며 이전 화면 방향을 재사용할 때 재생 세션·모의 관측 위치를 확인한다. 화면 방향은 실제 로봇 회전각이 아니다.
- AI: text first가 기본이며 Attach image로만 사진을 추가한다. Input JSON에서 전송할 텍스트를 볼 수 있다.
- Auto AI on NEW cue는 새 사건에서 요청한다. 동일 화면 구역의 요청은 30초 간격으로 억제하고, 중지·임무 변경·만료된 요청의 결과는 적용하지 않는다.
- 재관측 요청에는 화면 방향·이미지 영역·근거와 미확인 거리·각도를 담는다. translation_allowed=false이며 아직 실제 모터에 연결하지 않는다.
- 테스트 37개 통과. 합성 관절 입력에 대한 실제 로컬 텍스트 응답에서 inspect_person과 ID 5를 확인했다. 실제 부분 신체 영상의 검출 성능 시험과 GUI 영상 재시연은 진행하지 않았다.

> 노션 작업노트 게시용 원고. 코드 기반과 데이터 흐름을 설명하는 문서이며, 추가 영상 시연과 실물 통합은 별도로 진행한다.

## 1. 이번 작업의 목적

RoverAid는 카메라로 주변을 관측하고, 관측 결과와 탐색 진행 상황을 함께 이용해 다음 행동을 정하는 재난탐사 로버다. 노트북은 영상 인식과 상위 임무 판단을 담당하고, 로버 쪽은 센서 수집과 실제 주행을 담당하는 방향으로 구성한다.

기존 노트북 구현에서는 사람 탐지를 정지 신호로 연결했다. 이번 작업에서는 그 앞뒤에 필요한 정보를 구조화했다. 화면에 몇 명이 있는지, 어떤 대상을 계속 보고 있는지, 어떤 자세 후보인지 기록하고, 이를 탐색 후보·현재 임무와 함께 AI 판단에 전달하는 기반을 작성했다.

이번 개발 작업본은 노트북에서 독립적으로 확인할 수 있도록 분리했다. 기존 팀 저장소와 Pi/Pico 코드는 변경하지 않았다.

## 2. 전체 처리 흐름

```text
입력
  실제 영상 / 웹캠                         합성 지도 / 모의 로버 위치
        │                                         │
        ▼                                         ▼
  [영상 인식]                              [탐색 후보 생성]
  YOLO Pose: 사람 위치·키포인트               알려진 빈 공간 중
  ByteTrack: 프레임 사이 ID 연결              미탐색 영역과 맞닿은 곳 추출
  자세 규칙: 자세 후보·관측 누적               도달 가능 여부·거리·탐색 이득 계산
        │                                         │
        └──────────────────┬──────────────────────┘
                           ▼
                       WorldState
            현재 임무 · 관측 사람 · 탐색 후보
            모의 위치 · 방문 이력 · 영상 최신성
                           │
                           ▼
                    [로컬 VLM 판단]
                   Qwen3-VL 2B 모델
             현재 프레임과 상태 정보를 함께 입력
                           │
                           ▼
                 action / target_id / reason
                           │
                           ▼
                    [임무 관리자]
           허용 행동·대상 ID·영상 최신성 확인
                           │
                           ▼
                   NavigationAdapter
                           │
                           ▼
                   현재: MockNavigation
                 합성 지도에서 목표 이동·취소

각 단계의 입력·판단·발견 정보 → GUI 및 실행 기록
```

WorldState는 여러 모듈이 공유하는 ‘현재 상황 묶음’이다. AI가 영상 한 장만 보고 임의로 움직임을 정하는 대신, 프로그램이 정리한 관측과 선택 가능한 목표를 함께 보도록 한다.

## 3. 작성한 코드와 책임

| 모듈 | 주요 코드 | 입력 → 출력 |
|---|---|---|
| 영상 인식 | `Perception.process()` | 프레임 → 표시 영상, 현재 사람 목록, 추적 이력, 추론 시간 |
| 자세 후보 | `posture_candidate()` | 어깨·골반·무릎 등 키포인트 → upright / seated / lying candidate / unknown |
| 탐색 후보 | `MockMap.frontiers()` | 합성 occupancy grid·모의 위치 → 도달 가능한 frontier 목록 |
| 상태 구성 | `world_state()` | 관측, 지도 요약, 임무 → AI 입력용 구조화 상태 |
| 로컬 AI | `LocalReasoner.decide()` | 프레임 + WorldState → 제한된 JSON 판단 |
| 판단 검증 | `validate_decision()` | JSON 판단·현재 후보 목록 → 허용 또는 오류 |
| 임무 관리 | `MissionManager.apply()` | 유효한 판단 → 탐색 목표 요청, 확인·보고·대기 상태 |
| 주행 경계 | `NavigationAdapter`, `MockNavigation` | 목표 요청·취소 → 현재는 모의 이동 |
| 실행 기록 | `Recorder` | 관측·판단·이벤트 → JSONL, 발견 사진, summary.json |
| 화면·동시 실행 | `Console`, `VideoWorker` | 영상 처리와 AI 판단을 분리하고 결과를 한 화면에 표시 |

## 4. 사람 인식·추적·자세 후보

### 사람 검출

YOLO26n Pose 모델이 영상에서 사람의 bounding box와 관절 키포인트를 추정한다. bounding box는 이미지에서 사람을 둘러싼 사각형이고, 키포인트는 어깨·골반·무릎 같은 신체 위치다.

### 사람 추적과 인원 표시

ByteTrack을 사용해 연속 프레임 사이의 검출 결과를 연결한다. 한 사람이 여러 프레임에 나타날 때 임시 추적 ID를 붙여 관측을 누적한다.

- 현재 인원: 지금 프레임에서 추적 중인 사람 수.
- 세션 추적 수: 현재 재생 구간에서 만들어진 추적 ID 수.
- 관측 이력: 각 ID의 최초·최근 관측 시각, 관측 횟수, 신뢰도, 자세 후보.

추적 ID는 얼굴 인식이나 신원 확인 결과가 아니다. 긴 가림이나 화면 이탈 후에는 같은 사람에게 새 ID가 부여될 수 있어, 세션 추적 수를 고유한 실제 인원 수로 해석하지 않는다.

### 자세 후보

어깨와 골반을 잇는 방향, bounding box의 가로·세로 비율, 골반과 무릎의 상대 위치를 사용한다. 최근 최대 7회 관측 중 같은 후보가 최소 3회 나타나고 우세할 때 표시하며, 관절이 충분히 보이지 않거나 판단이 동률이면 `unknown`으로 둔다.

현재 분류는 기하 규칙에 따른 후보 판정이다. ‘누운 자세 후보’와 ‘부상자’는 구분하며, 부상 여부는 이후 추가 관측과 작업자 확인의 대상이다.

## 5. 탐색 후보는 누가 만드는가

프로그램이 지도의 알려진 빈 공간과 미탐색 공간의 경계를 찾는다. 이 경계를 frontier라고 한다.

```text
알고 있는 빈 공간       아직 모르는 공간
  로버 → · · · ·   |   ? ? ? ? ?
                    ↑
              다음 관측 위치 후보
```

현재 코드에서는 모의 로버 위치에서 도달 가능한 빈 공간만 검색하고, 경계 셀을 묶어 후보를 만든다. 후보마다 위치, 거리, 주변 미탐색 영역의 양과 점수를 계산한다.

AI는 이 후보를 직접 생성하는 대신, 프로그램이 제시한 후보 중 다음에 확인할 곳을 고른다. AI를 쓰지 않는 `Rule baseline`은 미탐색 영역의 양과 거리를 이용한 점수로 선택한다. 두 경로를 구분해 AI 판단의 효과를 비교할 수 있게 했다.

현재 지도 갱신·로버 위치·이동은 모두 합성 입력이다. 이 코드가 실제 LiDAR 지도를 만들거나 SLAM을 수행하는 것은 아니다.

## 6. 로컬 AI에 주는 정보와 받는 판단

사용 모델은 **Qwen3-VL-2B-Instruct Q4_K_M**이며, llama.cpp를 통해 노트북 내부에서 실행한다. VLM은 이미지와 문장을 함께 입력받는 모델이다.

입력 정보:

- 현재 영상 프레임.
- 작업자가 지정한 임무 문장.
- 현재 화면의 사람 ID·신뢰도·자세 후보·이미지 좌표.
- 모의 로버 위치와 방문한 목표 수.
- 프로그램이 계산한 탐색 후보의 ID·거리·미탐색 영역 규모.
- 영상이 마지막으로 갱신된 후 경과 시간과 입력 출처.

반환 형식의 예:

```json
{
  "action": "inspect_person",
  "target_id": "5",
  "reason": "Person track 5 is visible and has high confidence, with a clear bounding box."
}
```

| 행동 | 의미 | 대상 |
|---|---|---|
| `explore` | 다음 탐색 후보로 이동 요청 | 제공된 frontier ID |
| `inspect_person` | 탐색을 보류하고 사람 후보를 재확인 | 현재 관측된 track ID |
| `report` | 관측 결과를 작업자에게 보고할 상태로 전환 | 없음 |
| `hold` | 추가 정보를 기다리며 대기 | 없음 |

AI는 PWM, 조향각, 모터 속도 같은 저수준 구동 값을 만들지 않는다. 또한 사람의 화면 좌표를 실제 거리나 지도 좌표로 바꾸어 추측하지 않는다. 현재 `inspect_person`은 접근 주행이나 카메라 회전을 실행하는 기능이 아니라 확인 상태를 만드는 상위 판단이다.

## 7. AI와 일반 프로그램의 경계

| 처리 | 담당 방식 |
|---|---|
| 사람 위치·관절 키포인트 추정 | YOLO Pose 신경망 |
| 연속 프레임의 ID 연결 | ByteTrack 추적 알고리즘 |
| 자세 후보 결정·시간적 안정화 | 키포인트 기하와 관측 누적 규칙 |
| frontier 추출·도달 가능성 검사 | 지도 탐색 알고리즘 |
| 영상·상태를 종합한 다음 행동 제안 | 로컬 Qwen VLM |
| 허용 행동·대상·최신성 확인 | 임무 관리 프로그램 |
| 현재 모의 경로 생성·이동 | 합성 지도 기반 경로 탐색·모의 실행기 |
| 향후 실제 주행·구동 | ROS 2 주행 계층 및 Pi/Pico 제어 계층과 통합할 부분 |

YOLO와 Qwen은 제공된 사전학습 모델을 사용하며 이번 작업에서 새로 학습시키지 않았다. 직접 작성한 부분은 이 모델의 입출력을 프로젝트 상태와 연결하는 처리, 판단 검증, 모의 탐색, 기록과 실행 구조다.

## 8. 실행 구조와 기록

영상 작업 스레드가 프레임을 읽고 YOLO·추적을 수행한다. GUI는 최신 결과를 받아 화면을 갱신한다. 로컬 VLM 요청은 별도 작업 스레드에서 수행해 응답을 기다리는 동안 GUI 입력을 막지 않도록 했다.

AI 판단은 먼저 화면에 제안으로 표시한다. 이후 적용 요청을 받으면 현재 상태를 다시 확인하고 MockNavigation으로 전달한다. 재생 구간이 바뀌었거나 판단이 만료됐거나 목표가 사라졌다면 적용하지 않는다. 현재 사람 관측은 새 탐색 요청보다 우선한다.

저장 항목:

- `events.jsonl`: 발견, 판단 요청, AI 결과, 적용·거부, 모의 목표 도착 등의 시간순 이벤트.
- `session-...-track-...-first.jpg`: 세션별 최초 발견 화면.
- `summary.json`: 최신 상태, 추적 이력, 최근 판단, 입력 출처.
- `evidence.jpg`: 사용자가 저장한 관측 화면.

모의 실행과 실제 영상 관측을 화면·로그에 구분해 남긴다. AI 서버는 localhost에만 연결하며 외부 AI API를 사용하지 않는다.

## 9. 현재 확인 범위

코드 기반은 독립 실행 가능한 형태로 작성했다. 기본 임무·입력 검증·자세 규칙 테스트를 확인했으며, 초기 실행 점검에서는 공개 보행자 샘플의 다중 추적과 로컬 VLM 응답을 확보했다.

현재 노트북은 i5-1340P, RAM 약 32GB, RTX 3050 Laptop 4GB 구성이다. 설치된 PyTorch는 CPU 빌드이므로 이번 준비본은 CPU 실행 기준이다. 초기 점검의 VLM 판단 응답은 약 22초였으며, 연속 모터 제어가 아닌 상위 임무 판단에 사용한다.

이후 영상 시연과 통합 검증은 별도로 진행한다. 사람 탐지·자세 후보의 성능은 대상 크기·가림·촬영 각도 등에 따라 추가 확인한다.

## 10. 실제 로버에 연결할 때 필요한 것

```text
이번 노트북 모듈
  영상 인식 + WorldState + 상위 판단
                 │
                 ├── 입력: 실제 지도·위치·센서 요약
                 └── 출력: 목표 요청·취소·보고
                           │
                   ROS 2 입력 / 주행 어댑터
                           │
                    Pi · 센서 / 주행 계층
                           │
                    Pico · 모터 / 서보 제어
```

다음 통합에서 합의할 항목:

1. **지도·위치 형식:** occupancy grid, 지도 해상도·원점, 좌표계와 타임스탬프.
2. **주행 요청 형식:** 목표의 지도 좌표, 목표 ID, 취소 요청, 도착·실패 결과.
3. **센서 요약:** LiDAR·거리 센서 관측과 최신성, 로버 자세·이동 상태.
4. **사람 위치 추정:** 카메라 관측을 거리·방향 정보와 결합하는 방법. 현재 2D box만으로 실제 접근 목표를 만들지 않는다.
5. **역할 경계:** 노트북의 판단, 주행 프로그램의 경로 계산·회피, Pico의 저수준 제어와 정지 처리.

칼만필터는 위치·속도 추정의 잡음을 줄이고 시간에 따른 상태를 추정하는 계층에 들어간다. LiDAR의 움직이는 점을 사람 후보로 삼으려면 로버 자체 움직임 보정, 시간 동기화, 객체 추적과 카메라 확인이 추가로 필요하다. 이번 기반에서는 그 결과를 나중에 WorldState 관측으로 추가할 수 있도록 판단 입력과 실행 경계를 구분했다.
